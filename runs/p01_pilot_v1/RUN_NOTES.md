## 5% 目标下的描述性结果

“实际阻止比例”分母是通过 R2 筛选的正确 H0；包括检验拒绝和无法评估。
“危险放行”分母是通过 R2 筛选、旧端点误差超过 10% 的 H1。

| n | 策略 | 测试 H0 实际阻止比例 | 危险放行 |
|---|---|---|---|
| 50 | D | 5.46% | 22/90 |
| 50 | F | 2.99% | 3/90 |
| 50 | A-D 面板 | 5.46% | 14/90 |
| 50 | A/E/F 面板 | 4.16% | 3/90 |
| 200 | D | 6.38% | 3/77 |
| 200 | F | 3.91% | 3/77 |
| 200 | A-D 面板 | 5.08% | 4/77 |
| 200 | A/E/F 面板 | 3.78% | 3/77 |

不同方法的实际测试错误率并不相等；这些结果不能作为已完成的等实际错误率排名。
危险分母只来自 n=50 的 6 个任务和 n=200 的 4 个任务，跨任务证据仍有限。
每个 n 有 64 个外推结果不可用，保留在操作性指标中，风险标签明确为未知。

## 校准问题与下一步

v1 的经验 CDF 分数在参考最大值以外饱和。在 n=50、1% 目标时，A/E/F
的阈值达到可实现的分数上限，所有有效评估都不报警。这反映 v1 分数组合的
有限参考集尾部问题，不代表面板本身缺乏检出能力。

下一协议须在新的参考/校准/测试流上验证连续的 H0-only 分数尺度或其他
预先固定的组合规则，并报告校准重复的不确定性。不得优化或覆盖 v1。
正式确认还需要新方程分组划分、固定外推区域，以及完整 n/噪声网格。

## 重现与维护

`manifest.json` 保存本次生成时的源文件、环境和协议指纹。
`source_snapshot.json` 对应的快照在后续代码维护前逐个核对 SHA-256 后保存。
数据生成完成后，仅整理了导入、循环闭包绑定，并给 Windows 元数据原子替换
增加短暂文件占用重试；统计量、阈值规则和已有数据未因这些维护而改变。
分析器随后增加分数上限诊断，不改变 v1 的任何决策。

原样本单元在一次 Windows 进度文件占用中断后通过同指纹检查续跑，无重新抽样。
修改过代码后，重跑请使用新的 `runs/p01_*` 目录，原目录的指纹保护会拒绝覆盖。

独立核查入口：`python validation/audit_release_policy.py --run runs/p01_pilot_v1`。
`audit.json` 记录数据哈希和核查项；`replay.json` 位于 `runs/p01_inventory/`。
